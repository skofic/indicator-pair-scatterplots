# Indicator pair scatterplots

This repository is being created for the the [EUFGIS](http://www.eufgis.org) portal in the realm of the [FORGENIUS](https://www.euforgen.org/about-us/news/news-detail/forgenius-a-new-project-to-revolutionise-our-understanding-of-forest-diversity) project.

The goal is to create a database of tree species observations and environmental data than can be used to generate distribution maps and indicator pair scatterplots, both served in a web page.

## Background

The scientific background for this work comes from two studies: the [EU-Forest](https://www.nature.com/articles/sdata2016123) high-resolution tree occurrence dataset, and the [EU-Trees4F](https://www.nature.com/articles/s41597-022-01128-5) study.

The first is a collection of tree species occurrences, and the second is a study that joins the tree species occurrence dataset with present and modeled future environmental data to create current and modelled future [tree species distribution maps](https://www.nature.com/articles/s41597-022-01128-5/figures/2) and [indicator pair scatterplots](https://www.nature.com/articles/s41597-022-01128-5/figures/1). The web publication of distribution maps and indicator pair scatterplots will be the product of this work.

This repository can take advantage of other repositories that have generated data used by the EUFGIS portal, in which you can find additional information:

-  [metadata-external-databases](/Users/milko/Local/Development/Git/Projects/Metadata/metadata-external-databases), it contains environmental data that we could use, it includes [WorldClim](https://www.worldclim.org/data/index.html) and [Chelsa](https://www.chelsa-climate.org) grid data covering the project region.
-  [metadata-store](/Users/milko/Local/Development/Git/Projects/Metadata/metadata-store), it contains the data dictionary standards and metadata used in all the databases.
- [Local EU-Trees4F data](/Users/milko/Local/Development/Workshop/EU-Trees4F),  it is the data generated by the EU-Trees4F project stored locally.

## Products

The products expected from this work are:

- [Indicator pair scatterplots](https://www.nature.com/articles/s41597-022-01128-5/figures/1) as a web pane that can be integrated in the existing EUFGIS portal. These scatterplots will have three layers:
  - Base layer (gray dots in image): indicator pair values for all occurrence locations.
  - Middle layer (coloured dots in image): indicator pair values for occurrences of target species.
  - Top layer (not in image): EUFGIS gene conservation unit locations.
- [Tree species distribution maps](https://www.nature.com/articles/s41597-022-01128-5/figures/6) as a web pane that can be integrated in the existing EUFGIS portal. What is missing from the example images is the location of the gene conservation units plotted in the top layer of the distribution maps.

## Improvements

Both the maps and the scatterplots can be produced using the EU-Trees4F study data, but this data is [WorldClim](https://www.worldclim.org/data/v1.4/worldclim14.html) version 1.4, which is obsolete. The idea is to see if it is possible to replicate the workflow used to produce these products, using the latest [WorldClim](https://www.worldclim.org/data/worldclim21.html) version 2.1 data, and/or use [Chelsa](https://www.chelsa-climate.org) data.

## Plan

### 1. Scientific Study Phase

1. Study the [EU-Forest](https://www.nature.com/articles/sdata2016123) project and data. Among the things we want to take out of the study are:
   1. The distribution maps generated in that project show the location of the species as continuous areas, rather than a group of points which are represented in the data. I would like to understand how they were able to make that change and be able to replicate the technique they used , including understanding what additional datasets may have been used to interpolate and spread the point occurrences.
2. Study the [EU-Trees4F](https://www.nature.com/articles/s41597-022-01128-5) project and data. Among the things we want to take out of the study are:
   1. Understand the process that was used to join occurrence data with environmental data. I would like to be able to replicate the process, possibly using the latest [WorldClim](https://www.worldclim.org/data/worldclim21.html) version 2.1 of the data, or [Chelsa](https://www.chelsa-climate.org) data for this purpose.
   2. Understand how to obtain continuous color maps, just like point 1a.
   3. Make a selection of indicator pairs that scientifically make sense and that can be used in the scatter plots.
3. Study the [metadata-external-databases](/Users/milko/Local/Development/Git/Projects/Metadata/metadata-external-databases) repository that created the GeoService database of environmental data, in particular WorldClim and Chelsa which cover the project region.
4. Study the [metadata-store](/Users/milko/Local/Development/Git/Projects/Metadata/metadata-store) repository. Here you can find the metadata and standards used in all project databases and datasets.

#### Questions to Answer

- Can we substitute the old version of WorldClim data with other sources?
- Given the tree species observations dataset, can we create a system that can be fed environmental data and generate species distribution maps and indicator pairs scatter plots?
- If the above is not possible, can we use the existing EU-Tree4F data to generate maps and scatterplots?

#### Things to keep in mind

- What counts is thet solutions have a scientific background. If we operate in an alternative way, this must be backed by scientific evidence.
- We need grid data (or other types of data if you believe) because we want users to be able to indicate a location on the map and have the scatterplot pairs render that location in the scatterplot.
